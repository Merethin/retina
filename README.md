# retina

Live, worldwide WA nation & endorsement tracker

## Introduction

Retina is a program that uses NationStates's daily data dumps and happenings to re-construct a live in-memory cache of a small part of the game world, most notably nations' WA status, endorsements, and region of residence. This enables far more efficient querying of data, letting one for example gather highly accurate endorsement data for an entire region in one request, without touching NationStates's API at all (which would require one request per nation to gather endorsement data).

Retina also supports real-time subscriptions to listen for changes in cache data, such as nations moving regions, resigning from the WA, or endorsing each other. Beyond just knowing that a nation was endorsed, Retina's subscriptions let you know what their endorsement list looks like now that it has been endorsed. Using GraphQL, you can select exactly what data you want to be sent every time the cache entry updates.

Retina depends on two other projects of mine, [swash](https://github.com/Merethin/swash) for data dumps and [akari](https://github.com/Merethin/Akari) for happenings.

## How it Works

Retina operates on an in-memory _snapshot_ of all NationStates nations and regions. When the program is started, it generates an initial snapshot through the **bootstrap** phase, and then updates it with further happenings in real time.

#### The Bootstrap Phase

During the bootstrap phase, Retina first gets nation and region data from the `nations_dump` and `regions_dump` Postgres tables generated by swash. It then queries the `akari_events` table for two sets of happenings: _update events_ (happenings from the major update corresponding to the data dump) and _subsequent events_ (happenings from the end of the major update up to the present).

Entries in the data dump are generated when their corresponding nations or regions update, which means the snapshot currently has data from varying points in time. Therefore, update events are iterated through and only processed if they occurred after the region or nation they affect has updated _(Note: since nation endorsement lists are saved in the data dump prior to being verified, region update happenings are partially processed to invalidate any endorsements that would have been removed by the game immediately after)_. Any nation founds or refounds during update that did not get saved in the data dump are also processed and added to the snapshot.

After that, the snapshot should (almost!) reflect the state of the game immediately after the last major update. All that's left to do to complete the bootstrap is to iterate through subsequent events and apply them to the snapshot, in order to have it reflect the current state of the game.

#### Re-Running Bootstrap & Non-Updaters

You'll notice I added "almost!" to the earlier paragraph. This is because a small, specific set of nations is missing from the snapshot after every initial bootstrap: nations that were founded before major, and did not update during it. This is because of update surfing, whether intentionally or accidentally. The data dump only includes nations that updated in a region, as that's when the entry is generated.

You can trigger another bootstrap on a live Retina instance at any time, by performing a POST request to /bootstrap. This will probably be secured in the future, but the intent is for retina to be a private API that's used/exposed through other programs that offer specific functionality using it, not a public endpoint. Therefore, as long as you trust what you're running on the same machine and don't expose the Retina port, you shouldn't get any unintended bootstraps.

The intended use case for triggering another bootstrap is to refresh the snapshot with data from a new data dump (therefore, you'd usually do this once a day after running swash, probably through a cron job or other scheduled task). The advantage of doing this instead of restarting Retina altogether is that data for nations that skipped update will be pulled from the previous snapshot.
